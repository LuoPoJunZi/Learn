# 1.9 网页无障碍基础：让页面能看、能听、能用键盘操作

网页无障碍（Accessibility，常缩写为 a11y）不是“给页面额外加一个特殊模式”，而是让不同设备、不同能力和不同使用环境中的用户都能理解并操作页面。

例如，键盘用户需要看见焦点位置，屏幕阅读器需要知道输入框的名称，图片加载失败时仍需要文字说明。做好这些基础，也会让表单、移动端和自动化测试更稳定。

## 适合人群

- 已经会写基础 HTML 和 CSS 的新手
- 准备制作表单、导航、弹窗或交互组件的人
- 想改进本仓库静态网页案例的人
- 听说过 ARIA，但不知道什么时候该用的人

## 学习目标

读完后，你应该能：

- 优先选择有语义的原生 HTML 元素
- 为图片、表单和按钮提供可理解的名称
- 用键盘检查页面的主要流程
- 保留清楚的焦点样式和合理的标题结构
- 知道 ARIA 能补充什么、不能修复什么

## WCAG 的四个方向

Web Content Accessibility Guidelines（WCAG）把要求组织为四个原则：

| 原则 | 新手理解 | 例子 |
| :--- | :--- | :--- |
| 可感知 | 信息不能只依赖一种感官 | 图片有替代文本，视频有字幕 |
| 可操作 | 不只用鼠标也能完成操作 | Tab 能到达按钮，焦点清晰 |
| 可理解 | 内容和反馈容易看懂 | 标签明确，错误提示具体 |
| 健壮 | 能被浏览器和辅助技术正确解析 | 使用标准 HTML，状态标记正确 |

新手不必先背所有条款。先把下面的原生语义、文字替代、键盘和焦点做好，就已经能消除很多常见障碍。

## 第一原则：原生 HTML 优先

浏览器已经知道 `<button>`、`<a>`、`<input>` 和 `<select>` 怎么工作，也自带键盘和辅助技术支持。

不推荐：

```html
<div class="button" onclick="saveData()">保存</div>
```

推荐：

```html
<button type="button" onclick="saveData()">保存</button>
```

这两个元素看起来可以做成一样，但原生按钮天然支持：

- Tab 键聚焦
- Enter 或 Space 激活
- 禁用状态
- 屏幕阅读器识别为按钮

如果必须给 `<div>` 补 `role="button"`、`tabindex="0"` 和键盘事件，通常说明一开始就该用 `<button>`。

## 用结构表达含义

常见页面区域应使用合适元素：

```html
<header>站点页眉</header>
<nav aria-label="主导航">...</nav>
<main>
  <h1>文章标题</h1>
  <article>...</article>
</main>
<footer>站点页脚</footer>
```

标题应按内容层级组织，而不是为了字号随意跳级：

```text
h1 页面主题
└── h2 主要章节
    └── h3 章节中的小节
```

字号交给 CSS；标题级别负责表达文档结构。通常一个页面应有清楚的主标题。

## 图片替代文本怎么写

图片的 `alt` 取决于它在当前页面中的作用。

### 传递信息的图片

描述用户需要从图片中得到的信息：

```html
<img src="sales-chart.png" alt="7 月销售额比 6 月增长 18%">
```

不要只写“图片”“图表”或文件名。替代文本不必复述附近已经完整表达的内容。

### 纯装饰图片

如果去掉图片不影响理解，使用空替代文本：

```html
<img src="divider.png" alt="">
```

空 `alt` 会告诉屏幕阅读器忽略它。省略 `alt` 可能导致阅读器读出文件名，效果反而更差。

### 可点击图片

替代文本应描述操作目的：

```html
<a href="/">
  <img src="logo.png" alt="返回 Learn 首页">
</a>
```

## 表单必须有可理解的标签

仅使用 `placeholder` 不是合格标签。占位文字输入后会消失，而且通常颜色较浅。

推荐写法：

```html
<div class="field">
  <label for="email">邮箱地址</label>
  <input
    id="email"
    name="email"
    type="email"
    autocomplete="email"
    aria-describedby="email-help"
    required
  >
  <p id="email-help">用于接收订单确认，不会公开显示。</p>
</div>
```

`for="email"` 和 `id="email"` 建立关联。点击标签也能聚焦输入框，屏幕阅读器会读出控件名称。

多个选项属于同一问题时，使用 `<fieldset>` 和 `<legend>`：

```html
<fieldset>
  <legend>通知方式</legend>
  <label><input type="radio" name="notice" value="email"> 邮件</label>
  <label><input type="radio" name="notice" value="sms"> 短信</label>
</fieldset>
```

错误信息要说明“哪里错、如何改”，不要只用红色边框：

```html
<p id="email-error">请输入包含 @ 的有效邮箱地址。</p>
```

## 键盘操作检查

不用安装工具，先完成一次手工检查：

1. 刷新页面后，不碰鼠标。
2. 按 `Tab` 向前移动，按 `Shift + Tab` 向后移动。
3. 确认每个链接、按钮和表单控件都能到达。
4. 确认当前焦点始终清楚可见。
5. 使用 Enter 或 Space 激活按钮和选项。
6. 打开弹窗或菜单后，确认可以用 Escape 关闭，并回到合理位置。

网页的阅读顺序和 Tab 顺序应与视觉顺序一致。不要用很大的正数 `tabindex` 人工拼顺序，它通常会让维护更困难。

## 不要移除焦点轮廓

下面的样式会让键盘用户不知道自己在哪里：

```css
/* 不推荐 */
*:focus {
  outline: none;
}
```

可以使用 `:focus-visible` 提供与设计一致的清晰样式：

```css
:focus-visible {
  outline: 3px solid #0b63ce;
  outline-offset: 3px;
}
```

焦点样式需要在浅色、深色和图片背景上都看得见。不能只依赖轻微阴影或颜色变化。

## 颜色不是唯一信息

如果表单只把错误输入框变红，色觉差异用户可能无法判断。应同时提供文字和必要图标：

```html
<p class="error" role="alert">邮箱格式不正确，请检查后重试。</p>
```

正文与背景要有足够对比度。灰色小字、透明度过低的提示、文字覆盖复杂图片，都是常见问题。颜色对比可以使用浏览器开发者工具或专门检查器验证，不要只凭肉眼猜。

## 动态内容要有状态反馈

页面局部更新后，视觉用户能看到变化，屏幕阅读器用户不一定知道。简短状态可以使用直播区域：

```html
<p id="save-status" role="status" aria-live="polite"></p>
```

```javascript
document.querySelector("#save-status").textContent = "保存成功";
```

`polite` 会在合适时机播报，不会粗暴打断当前内容。不要把整个页面放进 `aria-live`，频繁播报会制造新的干扰。

## ARIA 应该什么时候用

ARIA 用来补充浏览器无法从原生 HTML 得到的名称、关系和状态，例如：

- 给多个 `<nav>` 提供不同的 `aria-label`
- 用 `aria-expanded` 表示折叠面板是否展开
- 用 `aria-controls` 关联控制按钮和目标区域
- 用 `role="status"` 播报异步结果

折叠按钮示例：

```html
<button
  type="button"
  aria-expanded="false"
  aria-controls="details"
>
  查看详情
</button>
<section id="details" hidden>...</section>
```

JavaScript 展开内容时，要同步更新 `hidden` 和 `aria-expanded`。只写属性、不更新真实行为，会给辅助技术提供错误信息。

记住：ARIA 不会自动增加键盘操作，也不会修复错误 HTML。能用原生元素时，优先使用原生元素。

## 常见错误

| 错误 | 更好的做法 |
| :--- | :--- |
| 用 `<div>` 模拟所有按钮 | 使用 `<button type="button">` |
| 图片统一写 `alt="image"` | 按图片用途写描述或空 `alt` |
| 输入框只写 placeholder | 使用可见 `<label>` |
| CSS 删除所有 outline | 提供清晰的 `:focus-visible` 样式 |
| 只用红绿表示状态 | 同时提供文字、图标或形状 |
| 为了“增强无障碍”到处加 ARIA | 先使用正确的原生 HTML |
| 用 CSS 调整视觉顺序，却不检查键盘顺序 | 保持 DOM、阅读和交互顺序一致 |

## 页面完成检查清单

- [ ] 页面有清楚的 `<title>` 和主标题
- [ ] 标题层级能反映内容结构
- [ ] 信息图片有合适的 `alt`，装饰图片使用 `alt=""`
- [ ] 表单控件有可见标签，错误提示说明修改方法
- [ ] 所有主要操作都能只用键盘完成
- [ ] 焦点始终清楚可见
- [ ] 信息不只依赖颜色表达
- [ ] 优先使用原生 HTML，ARIA 状态与真实界面同步
- [ ] 放大文字或缩窄窗口后没有重要内容丢失

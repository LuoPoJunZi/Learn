# CSS @scope：组件样式的上下边界

## 适合人群与目标

适合会写 CSS 选择器、理解 DOM 父子关系的初学者。完成后应能使用作用域根与下界，知道 `:scope` 在规则中的含义，并区分作用域匹配、继承和 Shadow DOM。

资料核验：**2026-10-30**，参考当前 MDN。`@scope` 已有实际浏览器实现，但旧浏览器或内嵌 WebView 不一定支持。不同语言文档的 Baseline 标签可能更新不同步，因此本页不将某个年份标签当作所有环境可用的保证，也不列未经本机验证的最低浏览器版本。

## 文件与打开方式

- [index.html](index.html)：作用域根、嵌入区域和外部区域的对比。

## 为什么需要样式边界

如果直接写 `article a`，文章里嵌入的独立小组件也可能被选中；随着页面变复杂，继续增加祖先选择器会让覆盖越来越难维护。

`@scope` 可以指定从哪个根开始匹配，并在某个下界前停止：

```css
@scope (.scoped-panel) to (.embedded) {
  :scope {
    border: 3px solid #1d4ed8;
  }
  a {
    color: rgb(29, 78, 216);
  }
}
```

- `.scoped-panel`：作用域根。
- `.embedded`：作用域下界，该元素及其子树不匹配此作用域内的规则。
- `:scope`：在这里指当前作用域根，可以给根本身添加样式。
- `a`：只影响有效作用域中的链接，不影响组件外部与下界内部链接。

作用域根、下界选择器本身不会简单地作为前缀拼进每个内部选择器的 specificity。遇到冲突时仍需理解来源、重要性、层、优先级与作用域接近度，不能认为“离得近永远赢”。

## 作用域不是完全隔离

`@scope` 约束规则匹配，不阻止普通继承。假如给根设置了 `color`，嵌入区域仍可能通过继承获得这个颜色，即使下界阻止 `a` 规则直接匹配。

本例直接给基础 `a` 与 scoped `a` 指定颜色，不靠根颜色展示边界，避免把继承误判为 `@scope` 失效。

它也不能：

- 阻止外部全局 CSS 匹配组件内部。
- 创建独立的 JavaScript、DOM 或权限环境。
- 消毒不可信 HTML，或隔离恶意脚本。

Shadow DOM 有自己的封装机制，但同样不是运行任意不可信代码的安全沙箱。不要把 CSS 组件封装当作安全边界。

## 为什么保留基础回退

基础链接始终是可读的灰色并带下划线。支持作用域时，只有根内部的链接变蓝；不支持时浏览器忽略 `@scope` 块，页面仍可阅读与操作。

`CSS.supports("selector(:scope)")` 只能检查伪类选择器，不代表支持 `@scope` 规则。本例创建临时样式表并检查 `CSSScopeRule`，随后核对三处链接的实际计算颜色。检测是辅助信息，不代替目标浏览器测试。

## 观察与验证

1. 初始状态：支持时组件内链接蓝色，下界内与外部链接灰色。
2. 点击“作用域根”按钮移除根类名：三个链接都应恢复基础灰色。
3. 再点一次：内部链接恢复蓝色，其他两处不变。
4. 页面会显示三项计算样式检查结果；不支持时明确跳过，不冒充通过。
5. 使用 Tab 聚焦按钮和链接、用 Enter 操作，确认焦点框可见。
6. 在开发者工具暂时禁用 `@scope` 块，核对页面内容和链接仍可使用。

计算颜色检查可能受到强制颜色模式、用户样式或扩展覆盖影响；这时应人工核对，不要为了让测试通过而关闭用户的辅助功能。

## 常见问题

- **使用嵌套选择器不就够了吗？** 嵌套主要改善组织方式，不自动建立此处的上下边界；见 [现代 CSS 实验台](../modern-css-features/README.md)。
- **组件外部规则仍影响内部？** 正常；本特性不是对外部 CSS 的全面屏蔽。
- **下界子树的文字还是继承了颜色？** 检查祖先继承与其他全局规则，不要只看当前作用域。
- **有 JS 检测就兼容所有旧浏览器吗？** 不是；本例依赖现代基础浏览器 API，旧环境仍须使用目标设备验证。

# 5.5 GitHub CLI 终端自动化

日常开发中，许多人习惯这样工作：在终端里写完代码并完成 `git commit`，然后切到浏览器打开 GitHub 网页，点击“New Pull Request”，输入标题说明，再切到 Actions 标签页刷新等待 CI 跑完；一旦 CI 报错，又在网页上展开折叠的日志排错。

这种在“终端”与“浏览器网页”之间的频繁切换极大地打断了专注力。**GitHub CLI (`gh`)** 是 GitHub 官方推出的命令行工具，它将 GitHub 的核心能力（Pull Request 审查与合并、Issue 管理、Actions 流水线实时日志追踪、Release 发布等）直接带入终端，结合脚本化还能轻松实现本地全自动化工作流。

---

## 适合人群

- 喜欢纯终端沉浸式开发，希望减少鼠标点击与浏览器标签页切换的开发者。
- 需要编写自动化 Shell 脚本批量管理 GitHub 仓库的运维与 CI/CD 工程师。
- 想要体验 GitHub 官方免费 AI 模型接口（GitHub Models）的技术爱好者。

## 学习目标

完成本章后，你应该能够：

- 在主流操作系统安装并使用安全的浏览器/SSH 令牌凭据登录 `gh`。
- 熟练使用 `gh pr`、`gh issue`、`gh run` 进行端到端日常协作。
- 使用 `gh run watch` 像跟踪本地进程一样在终端实时观察远端 CI 构建日志。
- 利用 `gh api` 搭配 `--jq` 表达式快速提取仓库元数据与自动化报表。
- 编写一个根据当前未提交改动自动生成标准 Commit 与 PR 的自动化助手脚本。

---

> [!IMPORTANT]
> **初学者注意：`gh` 不是 Git 自带的命令！**
> 在电脑上安装了 Git（运行 `git --version`）并不意味着自带了 `gh` 命令。`gh` 是 GitHub 官方独立的开源命令行客户端。请必须**先执行下方的【第一步：跨平台安装】**，在终端能识别 `gh --version` 之后再运行后续指令，否则会报错 `command not found`。

## 第一步：安装与登录认证

### 1. 跨平台安装

| 平台 | 安装命令 |
| :--- | :--- |
| **Windows** | `winget install --id GitHub.cli` 或 `scoop install gh` |
| **macOS** | `brew install gh` |
| **Ubuntu / Debian** | `sudo apt update && sudo apt install -y gh` |
| **Fedora** | `sudo dnf install -y gh` |

### 2. 交互式认证

在终端输入：

```bash
gh auth login
```

根据提示进行选择：
1. **What account do you want to log into?** -> 选择 `GitHub.com`
2. **What is your preferred protocol for Git operations?** -> 推荐选择 `SSH`（若未配置 SSH 密钥可选 `HTTPS`）
3. **How would you like to authenticate GitHub CLI?** -> 选择 `Login with a web browser`
4. 终端会给出一个 8 位的单次验证码，并在浏览器打开授权页面，点击批准即可完成绑定。

查看当前登录状态：

```bash
gh auth status
```

## 第二步：高频核心工作流速查

### 1. 极速提交与处理 Pull Request

```bash
# 从当前分支一键创建 PR（--fill 自动使用最后一次 commit 标题与说明，--web 可以在浏览器中预览）
gh pr create --fill

# 列出当前仓库所有处于 Open 状态的 PR
gh pr list

# 在本地快速检出别人提交的 PR 进行实机测试（无需手动添加 remote 分支）
gh pr checkout 42

# 在终端直接比对该 PR 修改了哪些代码
gh pr diff 42

# 代码审查通过，直接在命令行合并并清理远端分支
gh pr merge 42 --squash --delete-branch
```

### 2. 实时监控 GitHub Actions 流水线

过去查看 CI 失败原因需要不断刷新网页，现在只需：

```bash
# 查看最近的 Actions 运行记录
gh run list --limit 5

# 交互选择一次运行并观察 Job/Step 状态（不是实时日志流）
gh run watch

# 查看指定运行失败步骤的日志；把 123456 替换为 gh run list 中的 ID
gh run view 123456 --log-failed

# 重新运行这次运行中失败的 Job
gh run rerun 123456 --failed
```

### 3. Issue 敏捷管理

```bash
# 快速记录一个 Bug Issue
gh issue create --title "修复登录页移动端样式溢出" --body "在 iPhone 15 视口下登录按钮被遮挡" --label "bug"

# 查看指派给我且未关闭的 Issues
gh issue list --assignee "@me" --state open

# 快速关闭指定编号的 Issue
gh issue close 15 --comment "已在 commit ab12cd 中修复"
```

### 4. 发布正式版本 (Release)

```bash
# 为当前 Tag 创建 Release，并让 GitHub 根据近期合并的 PR 自动生成规范更新日志
gh release create v1.2.0 --title "v1.2.0: 性能优化与新特性" --generate-notes
```

## 第三步：进阶技巧——`gh api` 与 `--jq` 数据提取

`gh api` 封装了带有自动认证凭据的 GitHub REST 与 GraphQL 客户端，省去了手动拼写 `curl -H "Authorization: Bearer ..."` 的繁琐。

```bash
# 统计当前仓库 Star 数量与创建时间
gh api repos/{owner}/{repo} --jq '{stars: .stargazers_count, created_at: .created_at}'

# 获取当前仓库最近一次构建产物（Artifacts）列表
gh api repos/{owner}/{repo}/actions/artifacts --jq '.artifacts[] | {name: .name, size_mb: (.size_in_bytes / 1048576)}'
```

## 第四步：实战脚本——命令行智能提交助手

编写一个轻量本地脚本 `quick-pr.sh`，打通 Git 差异与 GitHub CLI：

```bash
#!/usr/bin/env bash
set -euo pipefail

# 1. 在任何提交或推送前检查认证、仓库与功能分支
command -v gh >/dev/null || { echo "请先安装 GitHub CLI"; exit 1; }
gh auth status >/dev/null
REPO_ROOT=$(git rev-parse --show-toplevel)
cd "$REPO_ROOT"
CURRENT_BRANCH=$(git branch --show-current)
case "$CURRENT_BRANCH" in
    main|master|trunk|"")
        echo "请先切换到功能分支，例如 git switch -c docs/update-guide"
        exit 1
        ;;
esac

# 2. 只提交用户明确暂存的内容；提前用 git add -- path/to/file 选择文件
if git diff --cached --quiet; then
    echo "没有已暂存修改。请先选择文件并检查 git diff --cached。"
    exit 0
fi
git diff --cached --check
git diff --cached --stat
SUMMARY=$(git diff --cached --stat | tail -n 1)

# 3. 提示输入提交描述
read -r -p "请输入 Commit 说明 (例如: fix: resolve login timeout): " MSG
if [ -z "$MSG" ]; then
    MSG="chore: automated update ($SUMMARY)"
fi

git commit -m "$MSG"

# 4. 推送到当前分支并一键发起 PR
git push -u origin "$CURRENT_BRANCH"

echo "正在通过 GitHub CLI 创建 Pull Request..."
gh pr create --title "$MSG" --body "自动生成的 PR。变更统计：$SUMMARY"

echo "PR 已创建。查看该 PR 的检查状态：gh pr checks --watch"
```

脚本使用 Bash，需要先在功能分支上手动暂存并检查要发布的文件。它会提交、推送到 `origin` 并创建 PR；示例里的主分支检查应按团队实际的受保护分支名称扩展。新手可在练习仓库中运行：

```bash
chmod +x quick-pr.sh
./quick-pr.sh
```

## 常见错误与排查

### 1. 报错 `HTTP 403: Resource not accessible by integration`
- **原因**：可能是 Actions 的 `GITHUB_TOKEN` 权限、Fork PR 事件限制、细粒度令牌或组织策略；并非统一由 OAuth scope 不足造成。
- **解决**：先用 `gh auth status` 确认认证类型，再检查工作流 `permissions`、事件和仓库访问权限。只有使用浏览器 OAuth 登录且确实需要修改工作流文件时，才按需扩展对应 scope：
  ```bash
  gh auth refresh -s workflow
  ```

### 2. 报错 `none of the git remotes point to a valid GitHub repository`
- **原因**：当前终端所在目录不是 Git 仓库，或者远端地址（`origin`）未指向 GitHub。
- **解决**：检查 `git remote -v`，确保 URL 格式为 `git@github.com:owner/repo.git` 或 `https://github.com/owner/repo.git`。

## 少量自查

1. **`gh pr checkout 42` 相比手动 `git checkout -b pr-42` 有什么优势？**
   - *参考答案*：`gh` 会自动解析该 PR 的发起者（哪怕是来自外部 Fork 仓库），自动添加必要的远端跟踪并拉取对应分支，一步到位。
2. **`gh run watch` 的主要使用场景是什么？**
   - *参考答案*：在终端观察指定 Actions 运行的 Job/Step 状态；需要日志时使用 `gh run view RUN_ID --log` 或 `--log-failed`。
3. **如何利用 `gh` 命令快速打开当前仓库对应的 GitHub 网页？**
   - *参考答案*：执行 `gh repo view --web` 或简写 `gh browse` 即可在默认系统浏览器中秒开该仓库。

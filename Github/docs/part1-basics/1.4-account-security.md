# 1.4 GitHub 账号安全：2FA、Passkey 与恢复方案

注册账号和配置 Git 之后，还要完成一件容易被新手忽略的事：给 GitHub 账号准备可靠的登录保护和恢复方式。

账号一旦丢失，受影响的不只是个人资料，还可能包括仓库、Issue、Pull Request、发布权限和团队资源。GitHub 官方明确说明：如果所有两步验证凭据和恢复方式都丢失，GitHub Support 不能代替你恢复账号。

## 适合人群

- 刚注册 GitHub、还没有开启两步验证的人
- 已经开启短信验证，但没有保存恢复码的人
- 经常在多台电脑或手机上登录 GitHub 的人
- 准备维护公开仓库、加入组织或参与开源项目的人

## 学习目标

读完后，你应该能：

- 区分密码、两步验证、Passkey、SSH 密钥和访问令牌
- 为账号配置至少两种可用的验证方式
- 安全保存恢复码，并完成一次恢复能力检查
- 识别不应上传到仓库的敏感凭据

## 先看懂五种凭据

| 凭据 | 主要用途 | 能否互相替代 |
| :--- | :--- | :--- |
| 密码 | 登录 GitHub 网站 | 不能代替 SSH 密钥或访问令牌 |
| 2FA 验证码 | 在密码之外确认“是你本人” | 不能用于 `git push` |
| Passkey | 使用设备解锁、指纹或安全密钥登录 | 可同时满足密码和 2FA，但仍要准备恢复方案 |
| SSH 密钥 | 让本地 Git 通过 SSH 访问仓库 | 不是网页登录的普通密码 |
| Personal Access Token | 通过 HTTPS 或 API 授权工具访问 GitHub | 应按最小权限创建，不能公开 |

最常见的误区是把 SSH 密钥和 Passkey 当成同一件事。它们都可能依赖公钥密码学，但使用场景不同：SSH 密钥主要服务于 Git 远程操作，Passkey 主要服务于网站登录和敏感操作确认。

## 推荐配置顺序

建议按下面顺序操作，不要只开一个验证方式就结束：

1. 确认邮箱已经验证，并且邮箱仍可正常接收邮件。
2. 开启 2FA，优先使用 TOTP 验证器，而不是只依赖短信。
3. 立即下载恢复码，存入可信密码管理器或离线安全位置。
4. 再添加一种备用方式，例如 Passkey 或硬件安全密钥。
5. 检查 SSH 密钥和访问令牌，删除不认识或不再使用的项目。

GitHub 官方建议配置不止一种认证方式，并优先使用 TOTP 和安全密钥作为比短信更可靠的方案。

## 开启两步验证

GitHub 网页菜单可能随版本调整，当前通常可以从以下位置进入：

1. 点击右上角头像。
2. 进入 **Settings**。
3. 打开 **Password and authentication**。
4. 找到 **Two-factor authentication**。
5. 按页面提示绑定验证器应用，并输入一次动态验证码完成确认。

验证器应用会生成随时间变化的一次性验证码。绑定时看到的二维码和密钥都属于敏感信息，不要截图发给别人，也不要放入公开笔记。

### 为什么不建议只用短信

短信可能受到换卡攻击、号码回收、漫游和无信号等因素影响。短信可以作为备用方式，但不应成为唯一恢复希望。

## 保存和验证恢复码

开启 2FA 后，GitHub 会提供恢复码。每个恢复码只能使用一次，它们是在手机丢失、验证器损坏时进入账号的重要后备方案。

推荐做法：

- 保存到可信密码管理器的加密条目中。
- 再保留一份离线副本，例如放在安全位置的加密存储设备中。
- 不要存进当前 Git 仓库、公开网盘、聊天记录或未加密截图。
- 生成新恢复码后，立即销毁旧副本，因为旧码会失效。

完成后做一次“恢复能力检查”：确认你知道恢复码放在哪里，并且在没有当前手机的情况下仍能取得它。不要为了测试而随意注销唯一登录设备。

## 添加 Passkey

Passkey 可以保存在支持的平台验证器、密码管理器或硬件安全密钥中。登录时通常使用设备 PIN、指纹或面容解锁，不需要手工输入密码和验证码。

添加前先确认：

- 设备或密码管理器支持 Passkey。
- Passkey 能同步到你的其他可信设备，或者你另有备用验证方式。
- 公共电脑不是保存 Passkey 的合适位置。

GitHub 中通常可在 **Settings -> Password and authentication -> Passkeys** 添加。完成后，可以在不退出当前会话的前提下，用另一浏览器或隐私窗口验证登录流程。

Passkey 很方便，但不能成为唯一的“救命绳”。设备丢失、账号同步异常或密码管理器不可用时，恢复码和另一种验证方式仍然重要。

## 检查 SSH 密钥和访问令牌

账号安全不只发生在登录页面。进入设置后定期检查：

- **SSH and GPG keys**：删除已淘汰电脑、来源不明或长期不用的密钥。
- **Developer settings -> Personal access tokens**：删除不用的令牌，缩小权限和有效期。
- **Applications**：撤销不再使用的 OAuth App 或 GitHub App 授权。
- **Sessions**：发现陌生设备或地点时，结束会话并修改密码。

访问令牌不要写进代码。需要在本地使用时，优先放到环境变量、系统凭据管理器或专用密钥存储中；需要在 GitHub Actions 中使用时，放到仓库或环境的 Secrets 中。

## 账号异常时怎么做

如果你怀疑账号被他人访问：

1. 在可信设备上修改 GitHub 密码。
2. 结束可疑会话。
3. 检查邮箱、2FA 方法、Passkey、SSH 密钥和访问令牌是否被增加或修改。
4. 撤销不认识的应用授权。
5. 检查仓库最近的提交、发布、Webhook 和组织操作。
6. 同时保护关联邮箱，因为邮箱常常是账号恢复链路的一部分。

如果只是丢失 2FA 设备，优先使用恢复码、已有 Passkey、安全密钥或 GitHub 提供的其他已配置恢复方式。不要相信声称可以“绕过 GitHub 2FA”的第三方服务。

## 常见错误

### 只在手机里保存恢复码

手机和验证器一起丢失时，恢复码也随之丢失。至少准备一个不依赖当前手机的安全副本。

### 把密钥或令牌提交到 Git

即使随后删除文件，敏感信息也可能仍存在于 Git 历史中。发现泄漏后，第一步是立即撤销或轮换凭据，而不是只删除文件。

### 多人共享一个 GitHub 账号

共享账号会让审计、权限回收和 2FA 管理变得困难。团队成员应使用各自账号，再通过组织和仓库权限协作。

### 看到陌生验证请求仍然批准

如果你没有主动登录，不要批准设备上的验证提示。先检查会话和账号活动。

## 完成检查清单

- [ ] 主邮箱已验证并可正常访问
- [ ] 已开启 2FA，且不只依赖短信
- [ ] 恢复码保存在至少一个独立、安全的位置
- [ ] 已配置 Passkey、安全密钥或第二种备用方式
- [ ] 已清理不再使用的 SSH 密钥、令牌和应用授权
- [ ] 仓库中没有密码、私钥、令牌或验证二维码

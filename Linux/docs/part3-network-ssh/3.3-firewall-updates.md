# 3.3 UFW 防火墙与自动安全更新

VPS 能通过 SSH 登录之后，下一步通常是限制公网入口并保持安全补丁更新。这篇教程以 Ubuntu Server 和 Debian 系发行版为主，介绍 UFW 与 `unattended-upgrades` 的安全操作顺序。

> 警告：远程修改防火墙可能把自己锁在服务器外。启用 UFW 前必须先放行实际 SSH 端口，并保留一个已经登录的终端窗口。重要服务器还应准备云厂商控制台、快照或其他带外恢复方式。

## 适合人群

- 刚购买 Ubuntu VPS、只会 SSH 登录的新手
- 已经部署网站，但不清楚哪些端口暴露到公网的人
- 想了解系统是否会自动安装安全更新的人
- 需要排查 UFW 日志或自动更新状态的人

## 学习目标

读完后，你应该能：

- 区分云安全组、主机防火墙和应用监听端口
- 按安全顺序启用 UFW，避免切断 SSH
- 添加、查看和删除最小化的端口规则
- 检查 Ubuntu 自动安全更新的配置、计时器和日志
- 知道哪些操作需要维护窗口和备份

## 三层网络控制先分清

| 层 | 在哪里配置 | 作用 |
| :--- | :--- | :--- |
| 云安全组 | 云厂商控制台 | 流量到达 VPS 前先过滤 |
| 主机防火墙 | VPS 内的 UFW/nftables | 控制进入当前系统的流量 |
| 应用监听 | Nginx、SSH、数据库等服务 | 决定程序在哪个地址和端口等待连接 |

三层需要一起检查。云安全组放行 3306、UFW 拒绝 3306，数据库仍不可访问；两层都放行，但数据库只监听 `127.0.0.1`，公网同样无法连接。

## 第一步：记录当前状态

先记录系统、登录方式和监听端口：

```bash
cat /etc/os-release
whoami
ss -lntp
sudo ufw status verbose
```

`ss -lntp` 中常见监听地址：

- `127.0.0.1:端口`：通常只允许本机访问。
- `0.0.0.0:端口`：监听所有 IPv4 地址。
- `[::]:端口`：监听 IPv6 地址，具体行为还受应用配置影响。

如果 UFW 显示 `inactive`，只代表它还未启用，不代表服务器没有云安全组或其他 nftables/iptables 规则。

## 第二步：确认实际 SSH 端口

不要默认 SSH 一定使用 22。可以查看有效配置：

```bash
sudo sshd -T | grep '^port '
```

再和监听端口交叉确认：

```bash
ss -lntp
```

如果服务器使用默认端口并且 UFW 存在 OpenSSH 应用配置，可以先放行：

```bash
sudo ufw allow OpenSSH
```

如果 SSH 使用自定义端口，例如 2222，应明确放行对应 TCP 端口：

```bash
sudo ufw allow 2222/tcp comment 'SSH'
```

执行后先查看规则，不要立刻关闭当前 SSH 会话：

```bash
sudo ufw status numbered
```

## 第三步：只放行业务需要的端口

网站通常需要 HTTP 和 HTTPS：

```bash
sudo ufw allow 80/tcp comment 'HTTP'
sudo ufw allow 443/tcp comment 'HTTPS'
```

数据库、Redis、管理后台等端口不要因为“连接不上”就直接向全网开放。更安全的选择通常是：

- 只监听本机地址。
- 仅允许可信来源 IP。
- 通过 SSH 隧道或内网访问。

仅允许一个可信来源访问某端口的示例：

```bash
sudo ufw allow from 203.0.113.10 to any port 5432 proto tcp
```

`203.0.113.10` 是文档示例地址，必须替换为你的真实可信来源。家庭宽带公网 IP 可能变化，配置前先确认运维方式。

## 第四步：启用并验证 UFW

确认 SSH 和业务端口已经在规则中后，再启用：

```bash
sudo ufw enable
sudo ufw status verbose
```

保持原 SSH 窗口不动，另开一个终端重新登录服务器。只有新连接成功后，才说明 SSH 放行规则基本正确。

还应从外部检查网站和必要服务。不要把“UFW 显示 active”当成全部验证结果。

## 删除或调整规则

查看带编号规则：

```bash
sudo ufw status numbered
```

删除第 3 条：

```bash
sudo ufw delete 3
```

删除后编号会重新排列，因此每删一条都要重新运行 `sudo ufw status numbered`。不要记住旧编号连续删除。

也可以按原规则删除：

```bash
sudo ufw delete allow 80/tcp
```

远程服务器不建议把 `sudo ufw reset` 当作普通排错命令，它会清除现有规则并可能破坏连接方案。

## 开启和查看防火墙日志

新手通常使用低级别日志就足够：

```bash
sudo ufw logging low
sudo ufw status verbose
```

较高日志级别可能快速占用磁盘。排查时可以先看内核日志：

```bash
sudo journalctl -k --grep='UFW' --since today
```

较旧的 systemd 版本如果不支持 `--grep`，可以查看内核日志后再手工搜索，或者检查系统是否生成 `/var/log/ufw.log`。日志位置取决于发行版和日志服务配置。

看到 `BLOCK` 不一定意味着服务器已被入侵。公网主机经常收到自动扫描，关键是确认被阻止的目标端口、来源频率，以及是否存在同一时期的异常登录或服务日志。

## 自动安全更新是什么

Ubuntu Server 通常通过 `unattended-upgrades` 自动应用安全更新。它和手工运行 `apt upgrade` 不完全相同：自动更新按配置选择允许的来源和软件包，并由 systemd 计时器定期触发。

先检查软件包和计时器：

```bash
dpkg -l unattended-upgrades
systemctl list-timers --all apt-daily.timer apt-daily-upgrade.timer
```

主要配置文件通常是：

```text
/etc/apt/apt.conf.d/20auto-upgrades
/etc/apt/apt.conf.d/50unattended-upgrades
```

查看配置时先读，不要直接覆盖整个文件：

```bash
sudo less /etc/apt/apt.conf.d/20auto-upgrades
sudo less /etc/apt/apt.conf.d/50unattended-upgrades
```

自动更新日志通常位于：

```text
/var/log/unattended-upgrades/
```

查看最近结果：

```bash
sudo ls -lah /var/log/unattended-upgrades/
sudo tail -n 100 /var/log/unattended-upgrades/unattended-upgrades.log
```

## 手工验证更新流程

日常检查可以运行：

```bash
sudo apt update
apt list --upgradable
```

先查看将要升级的包，再在合适时间执行：

```bash
sudo apt upgrade
```

自动更新程序提供预演方式，但输出较多：

```bash
sudo unattended-upgrade --dry-run --debug
```

如果命令不存在，先确认 `unattended-upgrades` 是否安装。生产服务器升级内核、数据库、容器运行时等关键组件前，应查看变更说明并准备回滚或快照。

## 更新后是否要重启

Ubuntu 某些更新会创建重启提示文件：

```bash
test -f /var/run/reboot-required && cat /var/run/reboot-required
```

需要重启不等于应该立刻重启。先确认：

- 当前是否处于维护窗口。
- 服务是否有冗余或可接受短暂停机。
- 数据是否已保存或备份。
- 重启后关键服务是否设置为自动启动。

重启后检查：

```bash
systemctl --failed
ss -lntp
```

再从外部验证 SSH、网站和业务接口。

## 常见错误

### 先启用防火墙，再想起 SSH 端口

这可能直接断开远程管理。正确顺序是：确认端口、添加允许规则、检查规则、启用、另开窗口测试。

### 云安全组和 UFW 规则互相矛盾

排查端口时要同时检查云控制台、UFW 和应用监听地址，不要只盯着一层。

### 为了方便把数据库端口开放给所有地址

公网暴露数据库会显著增加攻击面。优先使用本地监听、可信来源限制、内网或 SSH 隧道。

### 自动更新开启后就不再检查

自动任务也可能因锁冲突、磁盘满、软件源失败或配置错误而停止。应定期检查计时器和日志。

### 开最高日志级别后忘记关闭

高流量服务器可能快速增长日志。使用满足排障需要的最低级别，并关注磁盘空间。

## 完成检查清单

- [ ] 已记录实际 SSH 端口和当前监听端口
- [ ] 启用 UFW 前已放行 SSH，并保留原会话
- [ ] 只开放业务真正需要的端口
- [ ] 已用第二个终端验证新 SSH 连接
- [ ] 已同时检查云安全组和应用监听地址
- [ ] 已确认自动更新计时器和最近日志
- [ ] 知道更新后如何判断是否需要重启
- [ ] 关键服务器有控制台、快照或其他恢复方案
